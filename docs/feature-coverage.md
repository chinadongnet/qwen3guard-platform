# 原版功能覆盖与整改验收

核对基线：Git `305f664` 的 `app/main.py`、`app/static/index.html`、`app/static/app.js`、`platform_store.py` 和三个模型适配器。原八个页面的工具不能因为属于 Demo 而被删除。此前 P0/P1 首版遗漏了若干实用功能；本次按下面清单补回。

后续全量验收已完成，并进一步修复源标签丢失、审核对象混用、正则误拦、指标与大题库报告等问题；最新结论见 [全量模型质量验收](model-quality-acceptance.md)。下文的 34 项测试和“全库未跑”是功能恢复时的历史验收状态，后续记录已更新为 59 项测试及全量 GPU 执行。

此表描述业务功能覆盖，不表示旧管理接口可以继续匿名调用，也不表示所有旧 JSON 字段、错误码和 URL 都逐字兼容。新接口契约以登录后的 OpenAPI 为准。

## 哪些旧实现没有原样恢复，为什么

没有把题库、调测、对比、诊断、报表或演示样例判定为“没有意义”。以下是缺陷、空实现或需要明确边界的行为，保留其使用目的，不能恢复错误结论：

| 旧行为 | 证据 / 测试结果 | 当前处理 |
| --- | --- | --- |
| 题库中的 expected_unsafe 影响线上判断 | 固定文本与模型结果，旧 unsafe 标签使 Safe → Unsafe；旧 benign 标签使 Unsafe → Safe。新版保持原模型判断 | 题库只进入评测；不进入线上模型/规则决策 |
| 自定义允许关键词 | 旧命中分支只有 `pass`；更改 allow 列表前后结果完全一致 | 不提供无效开关。防误报通过提示词/阈值调测、放行样本回归和人工复核处理；自动白名单覆盖规则未实现 |
| 回复含“抱歉”等词就视为自拒答/合规 | “抱歉，会议延后到明天，请更新日程。”旧函数仍判 self_refused=True | 对比保留实际文本和审核证据；没有回复人工标签时不伪造合规准确率 |
| 预先分析完整文本，再逐 Token sleep/yield 却称实时熔断 | 旧 SSE 第 866 行先完成 scan，第 882 行才开始 yield | 保留诊断回放、Token 染色及速度参数；在线生成另走真正增量链路 |
| “100% 合规”“100% 零误报”等文案 | 上述标签泄漏证明原自测不独立；本次验收样本量也不足以支持保证 | 原报告保留为历史证据；不作为生产承诺 |
| 全局开关/上游设置仅写 JSON | 旧入口对 `enable_input_guard`、`enable_output_guard`、`enable_stream_guard`、`default_timeout_ms`、`max_Retries` 没有执行引用 | 超时、PII、通知已落到执行链路；关闭护栏的对比放入实验室；外部上游业务转发与可配置重试仍列 Todo |
| 明文列出所有 Key、匿名管理、永久清空审计 | 原基线已有匿名读取证据；新权限、隔离、密钥脱敏和归档测试通过 | 功能改为受控操作；不会恢复泄露与越权路径 |

可复现脚本：[verify_legacy_semantics.py](../scripts/verify_legacy_semantics.py)。
实际输出：[legacy-semantics-evidence.json](legacy-semantics-evidence.json)。这是实现机制测试，不是模型质量测试。
