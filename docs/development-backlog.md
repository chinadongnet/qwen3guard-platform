## 首轮接口与数据契约草案

新管理面采用 `/api/admin/*`，由用户会话和 RBAC 控制。旧 `/api/config`、`/api/gateway/*`、`/api/audit/*` 等必须同时加权限或转为受保护适配接口。

| 接口组 | 草案 | 核心约束 |
| --- | --- | --- |
| 身份 | `/api/admin/auth/login`、`/logout`、`/me` | 会话撤销、登录限速、禁止记录口令 |
| 应用 | `/api/admin/projects/{project_id}/applications` | 从会话验证 project 权限，不能信任请求体 tenant_id |
| 凭证 | `/api/admin/applications/{application_id}/keys`、`/{key_id}/rotate`、`/{key_id}/revoke` | 管理权限、只展示一次、轮换窗口、操作审计 |
| 检测记录 | `/api/admin/detections`、`/{request_id}` | 服务端项目范围、时间范围、游标分页、脱敏 |
| 运营 | `/api/admin/overview` | 返回过滤范围、时间粒度、时区、更新时间、指标定义 |
| 策略 | `/api/admin/policies`、`/{id}/versions`、`/{id}/publish` | 草稿不可直接影响生产；发布需当前版本校验 |
| 评测 | `/api/admin/evaluations`、`/{job_id}`、`/{job_id}/cancel` | 202 任务 ID、提交幂等、取消状态机、预算限制 |

以下为目标契约草案；当前实现以登录后的 `/openapi.json` 为准。当前 timings 提供 total 和 model_reported，尚未细分规则和排队时长。旧管理接口已受保护并返回 410，兼容范围见运行文档：

```json
{
  "request_id": "server-generated-id",
  "execution_status": "completed",
  "decision": "allow",
  "risk_level": "safe",
  "risk_score": 0.08,
  "score_kind": "policy_score",
  "findings": [],
  "policy": {"id": "policy-id", "version": 1},
  "model": {"id": "model-id", "revision": "pinned-revision"},
  "timings_ms": {"queue": 0, "model": 0, "rules": 0, "total": 0},
  "audit_id": "event-id"
}
```

策略版本和模型 revision 使用真实持久化值；模型无可确认 revision 时显示 unknown，不伪造。mask 决策按需返回 sanitized_content，不把用户原文无条件回显。技术错误返回统一 `{error: {code, message, retryable}, request_id}`；HTTP 401/403/413/422/429/503/504 分别定义。SSE 在响应头发送后遇错，通过约定 error 事件与终止记录处理，不能再伪装修改 HTTP 状态。

## 目标指标口径与测试门禁

当前首版总览计量单位为 detection_items（检测条目），聊天输入与终止审核分别计数；并非 HTTP 请求数。仅聚合对应环境的在线记录，排除评测、历史未知来源和流式中间窗口。HTTP 网关请求/拒绝率、独立长期计量和分阶段耗时仍在后续任务中。

- 请求量：指定项目、环境、时间窗内的生产 HTTP 请求；批量条目量另计。
- 阻断率：`block / 已完成检测条目`；mask、review、执行失败分别展示，不能混算为拦截成功。
- 技术成功率：按接口契约成功完成的请求占有效服务请求比例；4xx、429、5xx、超时单列。
- P50/P95/P99：端到端时长，包含排队，按接口和输入规模区分；流式另统计首个已审核片段时间和完整流时长。
- 评测准确率/召回率/误报率：仅在有独立标签的评测集或人工复核样本上计算，分母为零显示无样本。
- 生产记录必须有 source/environment；历史未知来源独立展示；计量不从有限保留的审计记录重算。

首轮必须覆盖的场景：

1. 匿名不可读取敏感管理数据；普通应用 Key 不可调用管理接口。
2. 项目 A 不可列举、查询、导出、复核项目 B 的记录；修改路径 ID 无法越权。
3. 创建后列表、错误、日志、OpenAPI 示例均不包含完整密钥；过期、禁用、撤销和轮换按契约生效。
4. 模型解析失败、OOM、队列满、超时不返回“安全”；请求取消不会错误释放仍运行的推理资源。
5. 数据库故障时返回可识别状态；已持久化记录重启可查，迁移前后数量和归属可对账。
6. 改变评测标签不会改变线上推理；中文、英文、正常问答、安全拒答、长输入有独立回归。
7. 前端登录、应用创建、接入验证、列表筛选、详情、退出完整可操作；空态、错误态可区分。
8. 旧数据面 API 保持已声明兼容；所有新旧管理入口执行一致权限。

GPU 端到端测试与无需 GPU 的契约/权限测试分离；CI 默认使用确定性假适配器验证工程逻辑，真实模型发布前执行独立集回归。假适配器结果不得作为模型质量证据。
